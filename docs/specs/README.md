## 스펙의 두 가지 형태
- **큰 스펙 (폴더)**: `docs/specs/<이름>/`에 `requirements.md`(무엇을), `design.md`(어떻게), `tasks.md`(작업 목록과 의존 그래프), `README.md`(색인). PR Lens의 단계별 스펙이 이 형태입니다.
- **작은 스펙 (파일 하나)**: `/spec`이 `_template.md` 형식으로 `docs/specs/<yyyy-mm-dd>-<slug>.md`를 만듭니다. 단계별 스펙에 없는 작은 기능에 씁니다. 스펙 하나가 PR 하나입니다.

## 큰 스펙을 읽는 법
파일이 커서 한 번에 읽히지 않습니다. 통째로 읽지 말고 다음 순서로 필요한 부분만 읽습니다.

1. 스펙 폴더의 `README.md`(색인)에서 절 위치와 결정 대기 항목을 확인합니다.
2. `tasks.md`에서 맡은 작업의 본문을 읽습니다. 본문 끝의 `_Requirements: …_`가 관련 요구사항 번호입니다.
3. `requirements.md`에서 그 번호의 인수 기준만 읽습니다.
4. `design.md`에서 그 작업의 클래스가 나오는 절만 읽습니다. 절 제목으로 찾습니다(줄 번호는 문서를 고치면 어긋납니다).

## 규칙
- 결정 대기(D-n, G-n)로 표시된 항목은 팀이 정합니다. 구현은 제안값으로 하고 임의로 확정하지 않습니다.
- 작업을 끝내면 `tasks.md`의 체크박스를 고칩니다. 설계와 다르게 구현했다면 같은 PR에서 설계 문서를 고칩니다.
- PR 하나는 `tasks.md`의 상위 작업 하나입니다. "PR 경계"가 적힌 작업은 그 경계대로 나눕니다(루트 `CLAUDE.md`, 플레이북 6장).
