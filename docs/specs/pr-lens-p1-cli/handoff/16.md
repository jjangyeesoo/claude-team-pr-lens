## ConfigLoader와 ConfigException의 호출 형태
결정: `new ConfigLoader(workingDir, homeDir).load(Path explicit)`로 읽는다. `explicit`이 null이면 현재 작업 폴더, 사용자 홈 순서로 `.prlens.yml`을 찾고 없으면 기본값을 돌려준다. `homeDir`은 호출하는 쪽이 `user.home`으로 만들어 넘긴다. `ConfigException`의 `getMessage()`가 문제 전체(`설정 오류 N건:` + 줄마다 `- 항목: 내용`)이므로 stderr에 그대로 쓴다. 비밀 항목은 값이 메시지에 없다
이유: `design.md`에는 클래스 이름만 있고 호출 형태가 없었다
영향받는 작업: 18.1(`--config` 값을 `Path`로 넘긴다), 18.2(`preflight`가 설정 단계에서 `ConfigException`을 받아 종료 코드 2로 바꾼다. 마스커를 먼저 설치한 뒤 부르므로 메시지는 마스킹된다), 18.5

## 설정 값의 읽기 규칙
결정: 숫자나 `true`처럼 읽히는 문자열 값은 큰따옴표가 필요하다(`model: 123`은 `llm.model` 오류). 값이 없는 섹션은 빈 섹션이다. 비용 상한은 반올림한 값이 `Configuration`에 담긴다
이유: 설정 파일의 의미를 정하는 요구사항이 없어 round-trip(18.11)에 필요한 형태로 정했다
영향받는 작업: 18.6(CLI 통합 테스트의 설정 사례는 이 규칙을 따른다), README(설정 예시를 쓴다면 문자열에 큰따옴표를 붙인다)
