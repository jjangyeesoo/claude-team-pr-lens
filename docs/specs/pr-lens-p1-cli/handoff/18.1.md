## ReviewRunner와 ReviewArgs
결정: `ReviewCommand`는 인자를 검증해 `ReviewArgs(String url, OutputFormat format, Path config)`를 만들고 `ReviewRunner.run(ReviewArgs)`(종료 코드 반환)에 넘긴다. `config`는 `--config`가 없으면 null이고 경로는 해석하지 않은 그대로다. `PrLensMain.main`의 runner는 임시로 "아직 구현되지 않았습니다"를 stderr에 쓰고 2를 돌려준다.
이유: `CliPipeline`이 18.2에서 만들어지므로 18.1은 인자 검증 틀까지만 둔다.
영향받는 작업: 18.2 (`main`의 임시 runner를 `CliPipeline.preflight` 호출로 바꾸고, URL 형식 검증은 여기서 `UsageException`으로 한다), 18.3, 18.5

## 인자 오류 처리 방식
결정: picocli `execute()`는 파라미터 예외 처리기가 던진 예외를 삼키므로 `PrLensMain.execute`가 `parseArgs`와 `getExecutionStrategy().execute`를 나눠 부른다. 인자 오류는 `UsageException`, runner의 `RuntimeException`은 그대로 던진다. `PrLensMain.run`은 `UsageException`만 stderr(`\n` 끝)에 쓰고 2를 돌려주며 나머지 예외는 던진다.
이유: 설계(`setParameterExceptionHandler`)대로는 종료 코드를 호출자가 정할 수 없다.
영향받는 작업: 18.5 (그 밖의 예외 → 종료 코드 매핑을 `run`에 더한다. 내부 오류 경로를 위해 `run`의 `catch`를 넓힌다)

## picocli 출력과 UTF-8
결정: `commandLine`이 `setOut`/`setErr`에 `new PrintWriter(stream, true, UTF_8)`를 넘기고 ANSI는 끈다. 넘기는 스트림은 `main`에서는 `System.out`/`System.err`다.
이유: picocli 기본 writer가 기본 문자 집합을 쓰는지는 확인하지 않았고, 명시하면 상관이 없다.
영향받는 작업: 18.2 (`MaskingPrintStream`을 설치한 뒤 `run`에 그 스트림을 넘긴다. `run`은 `out.flush()`만 하고 닫지 않는다)

## Preflight와 runner
결정: `CliPipeline.preflight(ReviewArgs, Map env, Path workingDir, Path homeDir)`가 `Preflight(PullRequestUrl url, OutputFormat format, Configuration config, String githubToken, String anthropicApiKey)`를 돌려준다(순서: URL → 설정 → 환경변수, 실패는 `UsageException`/`ConfigException`/`MissingSecretException`). 토큰은 `strip()`한 값이고 `toString`에는 비밀값이 없다. `CliPipeline.runner(env, workingDir, homeDir, ToIntFunction<Preflight> next)`가 검증 통과 때만 `next`를 부른다. `PrLensMain.main`의 `next`는 아직 "아직 구현되지 않았습니다"를 쓰고 2를 돌려주는 임시 구현이다.
이유: 조립(18.3)이 `Preflight`만 받으면 되게 하고, 검증 실패 때 외부 호출이 없음을 `next` 호출 수로 테스트하려는 것이다.
영향받는 작업: 18.3 (임시 `next`를 조립 함수 호출로 바꾼다. 출력은 `\n` 규칙대로 쓰고 flush한다), 18.5 (`PrLensMain.run`의 `catch (UsageException | ConfigException | MissingSecretException)`를 예외 전체 매핑으로 넓힌다), 18.6 (`main`의 스트림 설치·`close()`는 단위 테스트가 없어 하위 프로세스 테스트로 확인한다)

## main의 스트림 설치
결정: `main`이 환경변수로 `SecretMasker`를 만들고 `MaskingPrintStream.stdout/stderr`를 만들어 `System.setOut/setErr`로 바꾼 뒤 `run`에 넘긴다. `run`은 `out`·`err`를 flush만 하고, `close()`는 `main`이 `System.exit` 직전에 한다.
이유: 마스커를 가장 먼저 설치하고, Logback이 첫 사용 때 `System.err`를 잡게 하려는 것이다.
영향받는 작업: 18.4 (`StderrReporter`는 이 `err`를 받고 모든 메시지를 `\n`으로 끝낸다), 18.6
