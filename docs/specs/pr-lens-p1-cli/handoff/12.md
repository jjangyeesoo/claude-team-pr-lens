## 누적 비용 경고(costThresholdExceeded)는 분할 모드에서만 나간다
결정: `ReviewEngine`은 SPLIT에서만 누적 비용이 처음 상한을 넘을 때 `costThresholdExceeded`를 한 번 부른다(남은 Chunk 수 = 전체 - 현재 번호). 단가가 없어 Chunk 비용이 null이면 그 뒤로 누적을 멈추고 알리지 않는다. SINGLE, SUMMARY_ONLY, NO_TARGET에서는 부르지 않는다
이유: 요구사항 20.4는 분할 모드의 누적 경고이고, 20.3은 리뷰가 끝난 뒤 합친 추정 비용을 보는 경고라 서로 다르다
영향받는 작업: 18.x (CLI가 20.3 경고를 `ReviewResult.usage().estimatedCostUsd()`와 상한을 비교해 직접 낸다. 분할 모드에서 20.4 경고가 이미 나갔어도 20.3은 별도로 낼지는 CLI에서 정한다)

## 대상 0개 결과의 usage
결정: `NO_TARGET` 결과의 `usage`는 토큰 0, `model`은 `config.model()`, `estimatedCostUsd`는 `0.0000`이다. 단가 유무와 상관없다
이유: `null`이면 "단가 없음" 경고(요구사항 20.5)가 잘못 나간다
영향받는 작업: 18.x (단가 없음 경고는 토큰 수가 0보다 클 때만 의미가 있는지 CLI에서 확인), 15.x ResultCodec 픽스처

## AllChunksFailedException
결정: `review.AllChunksFailedException(int failedChunks, RetriesExhaustedException last)`를 만들었다. 메시지는 "분할 리뷰의 Chunk N개가 모두 실패했습니다: <last의 메시지>"이고 마지막 실패를 cause로 둔다. `failedChunks()`로 개수를 꺼낼 수 있다. `PrLensException`을 상속한다
이유: CLI는 `getMessage()`만 stderr에 쓰므로 요구사항 21.6의 API 이름, 마지막 상태, 시도 횟수를 메시지에 넣어야 한다. 설계 오류 표(design.md)도 이에 맞춰 고쳤다
영향받는 작업: 18.x (`ErrorMapper`는 이 타입을 따로 나누지 않아도 종료 코드 2로 매핑됨을 확인), P2 2.7 (`RunErrorKinds.of`는 cause 사슬을 따라가지 말고 바깥 예외 타입으로 먼저 판정해 `all_chunks_failed`로 분류한다. 안 그러면 cause의 `RetriesExhaustedException` 때문에 `llm_api`나 `network`가 된다)

## chunkStarted는 단일 모드에서도 나간다
결정: 엔진은 `chunkStarted(index, total)`을 NO_TARGET을 뺀 모든 모드에서 부른다. SINGLE과 SUMMARY_ONLY도 `chunkStarted(1, 1)`을 한 번 부른다
이유: 모드와 무관하게 Chunk 하나마다 한 번 알리는 것이 단순하다. "n/N" 진행 표시는 분할 모드에서만 필요하다(요구사항 13.12)
영향받는 작업: 18.3, 18.6 (`StderrReporter`가 `total > 1`일 때만 "n/N" 줄을 쓰게 하거나, 통합 테스트의 stderr 기대값에 이 줄을 포함한다), P2 11.1 (`JobReviewListener`의 `costThresholdExceeded`는 SPLIT에서 단가가 있고 실패하지 않은 Chunk의 누적이 상한을 처음 넘을 때만 호출됨)
