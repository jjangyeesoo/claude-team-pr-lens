# 작업 11.1~11.4 메모 (브랜치 feat/t1-p1-11.1-chunk-planner)

## ChunkPlanner의 정적 API
결정: `com.prlens.review.ChunkPlanner`(package-private, 정적 메서드)는 `decideMode(List<ChangedFile> targets, int sizeLimit): ReviewMode`, `plan(List<ChangedFile> targets, int sizeLimit): List<List<ChangedFile>>`, `changedLineCount(List<ChangedFile> targets): int`를 제공한다. `plan`은 모드와 무관하게 입력을 head 경로 코드 포인트 순으로 정렬해 greedy로 묶으므로, 엔진은 SPLIT일 때만 `plan`을 부르고 SINGLE이면 `List.of(targets)`를 Chunk 하나로 쓴다.
이유: design.md는 모드를 엔진 흐름에서 계산하고 `ChunkPlanner.plan(targets, L)`만 적었다. 모드 판정을 같은 클래스에 두어 13.1~13.9의 경계값을 한 곳에서 테스트한다.
영향받는 작업: 12.1 (`reportedChangedFiles` 비교와 `listener.modeDecided`, 대상 0개 분기는 엔진이 한다. `ReviewStats`의 Changed_Line_Count는 `changedLineCount(targets)`를 쓴다), 12.2(Property 27)

## 제외 파일 줄 수는 엔진이 뺀다 (요구사항 3.6)
결정: `ChunkPlanner`는 받은 `targets`의 줄 수만 센다. 제외 파일을 빼는 일은 `DiffFilter`가 돌려준 `targets`만 넘기는 것으로 처리하고, 플래너는 제외 파일을 알지 못한다.
이유: 플래너를 순수하게 유지한다. 3.6의 확인은 엔진 테스트(12.2 Property 11)로 넘긴다.
영향받는 작업: 12.1, 12.2

## DelimiterCodec만 만들고 감싸기는 11.5로 넘김
결정: `DelimiterCodec.escape`/`unescape`(package-private 정적)만 구현했다. 영역을 여는/닫는 `<prlens:…>` 태그로 감싸는 코드는 없다.
이유: 감싸는 코드는 `PromptBuilder`(11.5)에 있다. Property 33의 "감싼 영역에 태그가 정확히 하나씩"은 테스트 안에서 직접 감싸 확인했다.
영향받는 작업: 11.5 (파일 경로, 제목, 본문, head 스펙, diff 모두 `escape` 거친 뒤 감싼다. 컨텍스트 파일 내용도 포함)
