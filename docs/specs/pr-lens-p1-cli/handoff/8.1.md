# P1 작업 8.1 메모

## RepoTreeIndex와 BaseFileReader 시그니처
결정: `RepoTreeIndex.load(GitHubClient, RepoRef, sha)`/`of(RepoTree)`, `lookup(path)` → `Presence { FILE, DIRECTORY, ABSENT, UNKNOWN }`(commit=서브모듈은 `DIRECTORY`), `filesUnder(folder)` → `Optional<List<String>>`(모든 깊이의 blob, `String.compareTo` 오름차순, 폴더가 없으면 빈 목록, 잘린 트리면 `Optional.empty()`). `BaseFileReader(GitHubClient, RepoRef, baseSha, RepoTreeIndex, WarningSink).read(path)` → `Optional<String>`(내용은 받은 그대로). 모두 `com.prlens.context`의 package-private final 클래스다
이유: design.md는 `RepoTreeIndex` 이름만 정했고, 계획 `8.1-plan.md`의 `## 공통` 결정대로 구현했다
영향받는 작업: 8.2(`ClaudeMdCollector`), 8.4(`RuleCollector`), 8.11(`ContextCollector` 조립)

## 잘린 트리일 때 rule 건너뜀 경고
결정: tasks.md 8.1 본문의 "rule 수집은 경고 후 건너뜀"은 8.1에서 내지 않는다. `RepoTreeIndex.filesUnder`가 `Optional.empty()`를 돌려주는 것까지만 하고, 경고 `rules_skipped_tree_truncated`는 8.4의 `RuleCollector`가 낸다
이유: 계획의 슬라이스 나눔(경고는 rule 후보를 열거하는 쪽이 낸다)
영향받는 작업: 8.4

## rule 수집 시그니처와 경고 코드
결정: `RuleCollector(RepoTreeIndex, BaseFileReader, WarningSink).collect(List<ChangedFile> targets)` → `List<ContextFile>`(`RULE`, `BASE`, `.claude/rules` 아래 모든 깊이의 `.md` blob을 경로순으로 읽고 선택, 내용은 받은 그대로). 순수 부분은 `RuleSelector.select(List<RuleFile>, List<ChangedFile>)` → `RuleSelection(selected, warnings)`, `FrontmatterParser.parse(String)` → `Frontmatter(Optional<List<String>> paths, Optional<Problem> problem)`. 경고 코드는 `rules_skipped_tree_truncated`, `context_file_too_large`(BaseFileReader), `frontmatter_yaml_error`, `frontmatter_unclosed`, `frontmatter_invalid_paths`, `rule_glob_invalid`(무효 패턴당 1건), `rule_globs_all_invalid`(모두 무효면 앞의 패턴별 경고에 더해 1건). 모두 `com.prlens.context`의 package-private final 클래스다
이유: design.md는 `FrontmatterParser` 이름과 오류 종류만 정했고, 계획 `8.1-plan.md`의 `## 공통` 결정대로 구현했다
영향받는 작업: 8.11(`ContextCollector` 조립: `ClaudeMdCollector` 뒤에 `RuleCollector`를 같은 `RepoTreeIndex`·`BaseFileReader`로 부르고 `DiffFilter`의 `targets`만 넘긴다), 출력·보고에서 경고 코드를 다루는 작업
