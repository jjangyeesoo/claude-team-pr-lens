# 7.2 메모

## PullRequestUrl의 공개 형태
결정: `public final class PullRequestUrl`(생성자 private)에 `static Optional<PullRequestUrl> parse(String url)`, `RepoRef repo()`, `int number()`를 둔다. 형식이 틀리거나 번호가 2,147,483,647을 넘으면 예외 없이 빈 `Optional`을 돌려주고, `url`이 null이면 NPE다.
이유: design.md는 `repo()`·`number()`만 정했고, 실패를 알리는 `UsageException`은 `cli` 패키지 소유라 `pullrequest`가 예외 타입을 새로 두지 않는다.
영향받는 작업: 18.1(빈 값을 받으면 형식 예시가 담긴 `UsageException`을 던지고 요구사항 1.9의 메시지, stderr, 종료 코드 2를 처리한다)

## PrFetcher가 내는 경고 코드
결정: `PrFetcher`는 경고 두 종류만 낸다. `unknown_file_status`(design.md 표에 없는 GitHub 상태 문자열. `MODIFIED`로 담고 메시지에 정규화한 경로와 원래 문자열), `unparseable_patch`(메시지는 `DiffParseException.getMessage()` 그대로). 파일 수 부족(요구사항 1.14)과 PR 상태에 대한 경고는 내지 않는다.
이유: design.md는 표에 없는 상태 문자열을 정하지 않았고, 예외로 리뷰 전체를 막기보다 계속하는 편이 요구사항 1.1에 맞다. 파일 수 부족 판정은 엔진(Property 44), 경고는 CLI 몫이다(design.md "공유 경계").
영향받는 작업: 12.2(파일 수 부족 판정을 `reportedChangedFiles`와 `files.size()`로 한다), 18.x CLI(파일 수 부족 경고를 결과에서 유도한다. `PrFetcher`가 이미 냈다고 가정하지 않는다)

## 빈 patch와 복사 파일의 이전 경로
결정: `patch == null`만 `Absent`이고 `""`는 Hunk 없는 `Parsed`다. `previousFilename`이 있으면 상태와 관계없이(`copied` 포함) 정규화해 `previousPath`에 담는다(`ChangedFile` javadoc을 "이름 변경·복사일 때"로 고침).
이유: tasks.md 7.4의 결정 줄 참고. design.md가 `copied`→`ADDED`에서 이전 경로를 유지한다고 했다.
영향받는 작업: 컨텍스트 수집·리뷰 엔진(`ADDED`인데 `previousPath`가 null이 아닐 수 있다. `RENAMED`만 이전 경로가 있다고 가정하지 않는다)
