## MarkdownFormatter와 ExitCodeResolver의 호출 형태
결정: `new MarkdownFormatter().format(ReviewResult, ReviewContext)`는 `String`을 돌려주고, 그 끝은 항상 `\n` 하나다. `ExitCodeResolver.resolve(ReviewResult)`는 정적 메서드이며 0, 1, 3만 돌려준다. 결과를 만들지 못한 경우의 2는 호출하는 쪽(`cli`)이 정한다
이유: `design.md`에는 순수 함수라고만 있고 호출 형태가 없었다. 끝 줄바꿈은 `MaskingPrintStream`이 `\n` 없이 끝난 출력의 끝을 들고 있는 문제(18.2, 18.3 주의)를 피하려는 것이다
영향받는 작업: 18.3(Markdown 출력은 포매터가 `\n`으로 끝내므로 더 붙이지 않는다. `--format json`만 `ResultCodec.write` 결과에 `\n`을 붙인다), 18.5(`ExitCodeResolver`는 2를 내지 않는다)

## 구역 제목과 지적 형식
결정: 구역 제목과 지적 한 건의 형식은 `design.md`의 "구현 형식(작업 17.1)" 문단에 적었다. 라인이 있는 Finding은 파일별 지적, `summary_only`는 모두 라인 밖 지적에 나온다. 지적의 `message`와 `suggestion`은 이어지는 줄을 들여써서 목록 밖으로 나가지 않게 하지만, `summary`는 들여쓰지 않는다
이유: 요구사항이 구역 제목 문구를 정하지 않았다
영향받는 작업: 20.1(`expected.md`는 이 형식을 따른다. 손으로 쓰지 말고 포매터 출력으로 만든 뒤 검토한다), 20.2
