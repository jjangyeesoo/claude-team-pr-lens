## ResultCodec과 CodecException의 형태
결정: `ResultCodec`은 인스턴스(`new ResultCodec()`)로 쓰고 `String write(ReviewResult)`, `ReviewResult read(String)`을 가진다. `CodecException`은 `PrLensException`의 하위 타입이며 `path()`(문법 오류면 null), `allowed()`, `line()`, `column()`을 가진다. 생성자는 패키지 전용이다. 출력은 2칸 들여쓰기와 `\n`이고 끝에 줄바꿈이 없다
이유: `design.md`에는 클래스 이름만 있고 시그니처가 없었다
영향받는 작업: 18.3(`--format json`은 결과 끝에 `\n`을 직접 붙여야 한다), 18.5(`CodecException`을 종료 코드 2로 매핑), 20.1(픽스처 로더가 `read`를 쓸 수 있다), 20.2

## 읽기 쪽 검증
결정: `schemaVersion != 1`, `inline_eligible`이면서 `line` null, `line_missing`이면서 `line` 있음은 `CodecException`으로 거부한다. 선택 필드는 키가 없어도 null로 받는다
이유: 17.1의 (경로, 라인) 정렬이 null `line`을 견디지 않아도 되게 하기 위해서다. `schemaVersion`은 요구사항에 동작이 없어 거부로 정했다
영향받는 작업: 17.1(`inline_eligible`인 Finding의 `line`은 항상 있다. `summary_only`인 Finding은 `line`이 null일 수 있다), 20.1(픽스처의 `expected-result.json`은 이 조건을 지켜야 한다)
