## GlobMatcher의 무효 패턴 처리와 256개 상한

결정: `GlobMatcher.matches`와 `validate`는 무효 패턴이면 `GlobSyntaxException`(unchecked)을 던진다. 중괄호는 모두 펼친 뒤(상한 256개) 펼친 패턴마다 접두어 제거와 `**` 검사를 한다(`design.md`에 반영함).
이유: 문법 오류를 한 곳에서 판정하고, 요구사항 5.8의 "펼친 뒤 하나라도 일치" 모델과 정확히 같게 한다.
영향받는 작업: 8.4 (rule `paths` 패턴은 먼저 `validate`로 걸러 무효 패턴만 빼고 경고한 뒤 남은 패턴으로 `matches`를 부른다. 그러지 않으면 무효 패턴 하나로 리뷰 전체가 오류로 끝난다), 16.1 (`exclude.add`와 `exclude.remove` 모두 `validate`한 뒤 `Configuration`을 만들고 exit 2. `DiffFilter.apply`는 `additionalExcludes`에 무효 패턴이 남아 있으면 예외를 던진다. `remove`는 문자열 정확 일치만 보므로 `./**/*.png`는 `**/*.png`를 해제하지 않는다)

## 비밀정보 해제 무시 경고의 코드

결정: `DiffFilter`가 `FilterOutcome.warnings`에 담는 경고는 `Warning("exclude_unlock_ignored", "비밀정보 제외 패턴은 해제할 수 없어 요청을 무시했습니다: <패턴>")`이고 무시한 비밀정보 패턴마다 한 건이다(같은 패턴을 여러 번 해제해도 한 건).
이유: 설계에 코드 이름이 없어 이 작업에서 정했다.
영향받는 작업: 8.11 (`tasks.md` 12.1은 `DiffFilter`의 경고를 버리므로 `FilterOutcome.warnings`를 `WarningSink`로 넘기는 곳은 수집기인 8.11)
