## BaseFileReader.fetch와 Outcome
결정: `BaseFileReader`에 중첩 sealed `Outcome`(`Found(content)`, `Missing`, `Directory`, `TooLarge`)과 `Outcome fetch(String path)`를 더했다. 트리 색인으로 없음·폴더를 알면 요청하지 않고, 1MB 초과는 `context_file_too_large` 경고를 내고 `TooLarge`를 돌려준다. `read`는 `Found`일 때만 내용을 돌려주도록 바꿨고 동작은 같다.
이유: 404와 폴더를 나눠야 import 경고를 구분할 수 있다(tasks.md 8.6 주의).
영향받는 작업: 8.9(스펙 조회의 base 조회에 쓸 수 있다. head 조회는 색인을 거치지 않는 `getFile(repo, path, headSha)`로 해야 한다)

## ImportResolver API
결정: package-private `ImportResolver(BaseFileReader, WarningSink)`, `List<ContextFile> resolve(List<ContextFile> collected)`. `collected` 가운데 출처 `CLAUDE_MD`만 시작점으로 쓰고 모든 경로를 "이미 담긴 경로"로 본다. 돌려주는 것은 새 `IMPORT`(`Revision.BASE`) 파일뿐이고 BFS 순서다. `collected`의 경로는 정규화된 문자열 그대로 비교한다.
이유: 출처 우선순위 누적은 `ContextCollector`의 몫이다.
영향받는 작업: 8.11(`ContextCollector`가 CLAUDE.md 수집 뒤 `resolve`를 부르고 정규화된 경로를 넘겨야 한다)

## import 경고 코드
결정: `import_outside_repo`, `import_depth_exceeded`, `import_not_found`, `import_is_directory`. 1MB 초과는 `context_file_too_large`만 낸다.
이유: 설계에 코드가 없어 정했다.
영향받는 작업: 8.11, CLI 경고 출력
