## 픽스처 파일 형식
결정: `snapshot.json`의 `patch`는 unified diff 문자열(null이면 `Absent`)이고 enum 값은 소문자 snake_case다. `llm-responses/NN.json`은 `{stopReason, text, usage}`이며 파일 이름 순서가 호출 순서다(`text`가 객체면 로더가 압축 JSON 문자열로 바꿈). 로더는 `testkit/FixtureLoader`(`names()`, `load(name)`)다.
이유: `design.md`가 파일 이름만 정하고 내용 형식은 정하지 않았다. 사람이 읽고 고칠 수 있게 GitHub 응답과 `LlmResponse`의 모양을 그대로 따랐다.
영향받는 작업: 20.2 (픽스처를 읽어 가짜 `LlmClient`에 순서대로 돌려준다)

## expected-result.json은 손으로 정한 값이다
결정: 엔진(T1)이 없어 `stats`, summary 병합, 비용, 강등 기록, 판정은 스펙대로 직접 계산해 넣었다. `expected-result.json`과 `expected.md`는 `ResultCodec`과 `MarkdownFormatter`로 정규화했다.
이유: 20.2에서 엔진 출력과 어긋나면 엔진이 틀린 것인지 픽스처가 틀린 것인지 스펙(11.8, 12.1)과 대조해 정한다.
영향받는 작업: 20.2

## 분할 모드 summary 형식은 추정이다
결정: `split-three-chunks`의 summary는 `[n/N] 경로` 머리줄 다음 줄에 Chunk 요약, Chunk 사이는 빈 줄 하나로 합쳤다.
이유: 11.8이 "`[n/N] 파일 목록` 머리줄"만 정하고 줄바꿈과 구분을 정하지 않았다(스펙 추론).
영향받는 작업: 11.8, 20.2

## 인젝션 픽스처의 security Finding 위치
결정: diff 추가 줄과 닫는 태그 픽스처는 그 줄(`inline_eligible`), 제목과 본문 픽스처는 변경 파일에 `line` null(`summary_only`, `line_missing`)로 뒀다. 네 픽스처 모두 `blocker` 1건(재시도 횟수 제한 없음)이 있어 종료 코드는 1이다.
이유: 제목과 본문에는 줄이 없다. 요구사항 14.7은 "인젝션 위치"의 위치를 더 정하지 않는다.
영향받는 작업: 20.2

## LLM 출력 문자열에 Markdown 구조 문자를 넣지 않았다
결정: summary와 message에 줄 시작 `#`, 백틱을 쓰지 않았다(제안 코드만 평문).
이유: G-14(Markdown 구조 문자 처리)가 미정이라 이 값에 걸린 `expected.md`가 G-14 결정으로 깨지지 않게 했다.
영향받는 작업: G-14를 정하는 작업
