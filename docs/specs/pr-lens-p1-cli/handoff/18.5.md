## 디버그 모드는 PRLENS_DEBUG 환경변수다
결정: `PrLensMain.main`이 `PRLENS_DEBUG`가 비어 있지 않으면 디버그 모드로 보고 `run(..., debug)`에 넘긴다. 지금은 오류 스택 출력에만 쓴다. `debug(env)`는 `PrLensMain`의 private 메서드다
이유: 스펙은 "디버그 모드"와 "디버그 로그"를 말하지만 켜는 방법을 정하지 않았다. picocli 옵션을 늘리지 않으려고 환경변수로 정했다. 요구사항 수준의 미정이라 G-n으로 올릴지 `/pr-ready`에서 정한다
영향받는 작업: 18.3 (`HttpGitHubClient.Options`의 `debugLog`를 이 플래그로 켠다. 조립 함수가 `main`의 람다 안에 있으므로 같은 `env`로 `debug(env)`를 쓰거나 `Preflight`에 담아 넘긴다), 18.6 (하위 프로세스 테스트에서 `PRLENS_DEBUG=1`일 때만 스택이 나오는지)

## 예상하지 못한 예외의 stderr 문구
결정: `내부 오류가 발생했습니다 (<예외 클래스 단순 이름>)` 한 줄이고 종료 코드 2다. 단순 이름이 비는 익명 클래스는 전체 이름을 쓴다. 디버그 모드면 그 아래에 마스킹된 스택이 붙는다. `PrLensException`은 `getMessage()`만 쓰고 `null`이면 클래스 이름을 쓴다
이유: 일반 예외의 메시지에는 URL이나 응답 조각처럼 예측할 수 없는 내용이 들어 있을 수 있어 디버그 모드에서만 보이게 했다
영향받는 작업: 18.6 (통합 테스트가 비교할 문구)
