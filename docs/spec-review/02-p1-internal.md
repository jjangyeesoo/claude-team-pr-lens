# 02. P1 스펙 내부 정합성

[← 목차](README.md)

대상: `P1-req`(445줄), `P1-des`(910줄), `P1-tasks`(368줄), `docs/study-project/PRD.md`, `ROADMAP.md`. 모두 끝까지 읽었습니다.

## 총평

**판정: 작은 수정 후 시작 가능.** 그대로는 월요일 선머지(작업 1~4)를 시작하면 안 됩니다.

번호 참조는 정확합니다. 요구사항 22개, 인수 기준 222개, 속성 43개, 말단 작업 87개 사이에 없는 번호를 가리키는 참조는 0건이고, 의존 그래프에도 누락·중복이 없습니다. 문제는 네 군데에 몰려 있습니다.

- **공유 경계**: 트랙 사이 호출 시그니처와 경고 전달 방식이 정의되지 않았고, 예외 계층은 설계대로면 컴파일되지 않습니다.
- **스타터와의 불일치**: 설계는 스타터가 없다고 가정했지만 실제로는 있고, 패키지 배치가 승인된 ADR 0001과 다릅니다.
- **PRD 보안 요구 누락**: 리뷰 대상 저장소 한정이 P1 CLI에 없습니다.
- **선행 산출물 부재**: ADR 0003~0006과 spike 기록이 없어 T1의 Claude 어댑터와 실행 패키징은 착수할 수 없습니다.

발견 사항 1~8번을 고치면 T2·T3의 순수 함수 작업과 T1의 파서·검증기는 바로 시작할 수 있습니다.

## 발견 사항

### 치명

**1. [모호] 공유 경계에 트랙 간 호출 시그니처가 없습니다.**
- 위치: `P1-des:146-171, 175, 814` / `P1-tasks:35-40, 175, 305-306`
- 문제: 공유 경계 코드에 `PrFetcher.fetch`, `ContextCollector.collect` 시그니처가 없습니다(시퀀스 다이어그램 118, 122줄에만 있음). `LlmRequest` 필드, `RetryListener`, `Warning(code, message)`의 패키지와 전달 경로도 없습니다. 작업 8.11은 "목록으로 반환하거나 리스너로 전달"로 미정입니다. T3의 18.3·18.4가 T2 구현 없이 진행할 수 없습니다.
- 수정안: 작업 2.3에 두 시그니처, `LlmRequest`/`LlmResponse` 필드, `Warning`과 `WarningSink`(또는 반환 타입)를 넣어 월요일에 확정합니다.

### 중요

**2. [오류] 예외 계층이 설계대로면 컴파일되지 않습니다.**
- 위치: `P1-des:798` / `P1-tasks:54, 308`
- 문제: `PrLensException`(sealed)의 하위 타입이 `cli`, `config`, `github`, `support`, `review`에 흩어져 있습니다. Java 17은 이름 없는 모듈에서 sealed의 하위 타입을 같은 패키지에만 허용합니다(스타터에 `module-info.java` 없음). 또 기반 타입은 18.5(wave 9)에서 만드는데 하위 타입은 3.1(wave 2)에서 먼저 만듭니다.
- 수정안: sealed를 빼고 일반 추상 클래스로 두며, `support`에 넣어 작업 2.3 또는 3.1로 옮깁니다.
- 참고: Java 언어 규칙에 근거한 판단이며 실제로 컴파일해 보지는 않았습니다.

**3. [모순] 설계가 스타터를 없다고 전제하고, 패키지 배치가 ADR 0001과 다릅니다.**
- 위치: `P1-des:15, 77-94` / `repo/docs/adr/0001-feature-based-packages.md`
- 문제: 설계는 "이 워크스페이스에는 스타터가 없습니다"라고 적었지만 `claude-team-prlen/backend`가 있습니다(패키지 `com.example.starter`, Spring Boot 4.1.1). ADR 0001은 "`<feature>.{domain,api}` 구조", "공통 코드는 `common/`"인데, 설계는 `com.prlens` 아래 평면 14개 패키지와 `model`/`support`를 씁니다.
- 수정안: ADR-0003에서 CLI 모듈의 예외 규칙을 명시하거나 패키지 표를 ADR 0001에 맞춥니다. `P1-des:15` 문단을 실제 상태로 고칩니다.

**4. [누락] PRD의 리뷰 대상 저장소 한정이 P1에 없습니다.**
- 위치: `PRD.md:106` / `P1-req` 전체
- 문제: PRD 보안 항목 "리뷰 대상은 연구회 저장소와 공개 저장소로 한정"에 해당하는 요구사항이 P1에 없습니다. 요구사항 1은 임의의 github.com 저장소를 받습니다. P2 스펙에는 "Requirement 3: 리뷰 대상 저장소 한정"이 있습니다.
- 수정안: 요구사항 추가. 설정의 허용 저장소 목록 또는 공개 여부 확인에 실패하면 Claude 호출 전에 종료 코드 2. 최소한 범위 밖임을 명시합니다.

**5. [모순] 트랙 간 의존이 선언된 것보다 많습니다.**
- 위치: `P1-tasks:10` vs `198, 218, 234` / `P1-des:64, 173` / `ROADMAP.md:56`
- 문제: tasks는 트랙 간 의존을 `ConfigLoader`→`GlobMatcher` 하나만 선언합니다. 실제로는 T1이 T2 산출물 세 개에 의존합니다: 10.4→`LineRanges`(5.3), 11.5→`DiffPrinter`(5.2), 12.1→`DiffFilter`(6.3). ROADMAP의 "이 타입만 보고 병렬로 진행"과 어긋납니다.
- 수정안: 5.2, 5.3, 6.1, 6.3을 T2 최우선 선머지로 명시하거나 선머지 범위로 옮깁니다.

**6. [모호] ADR과 spike 산출물이 없고, 의존 작업 목록이 불완전합니다.**
- 위치: `PRD.md:142-153` / `P1-des:346-358, 901-905` / `P1-tasks:342`
- 문제: ADR 0003~0006이 `repo/docs/adr`에 없고(0001, 0002만 있음) `docs/spikes`도 없습니다. tasks Notes는 spike 의존을 13.1, 15.1, 18.7로만 적었지만 10.2(Jackson 패키지), 16.1(YAML 모듈), 3.1/13.2(`retry-after` 헤더 접근), 2.1(`Configuration.defaults()`의 effort·단가)도 의존합니다.
- 수정안: 결정 대기 표에 spike 항목과 막는 작업을 추가하고, 미결이면 임시값과 교체 지점을 작업에 적습니다.

**7. [모순] 스키마 제약이 요구사항, 설계, 작업에서 서로 다릅니다.**
- 위치: `P1-req:204` / `P1-des:286, 306, 309` / `P1-tasks:186`
- 문제: 요구사항 9.3은 스키마에 `line` 1 이상, `message` 1자 이상을 지정하라고 합니다. 설계는 그 제약이 SDK에서 지워진다고 적고도 스키마에 `"minimum": 1`, `"minLength": 1`을 넣었고, 10.1은 이를 스냅샷으로 고정합니다.
- 수정안: 9.3을 "로컬 검증으로 보장"으로 고치고, 전송 스키마에서 두 키워드를 빼고, spike 목록에 넣습니다.
- 참고: [05번 문서](05-external-facts.md)에서 이 두 키워드가 구조화 출력에서 지원되지 않아 400 오류가 난다고 확인했습니다.

**8. [모호] 팀 컨텍스트가 "따르지 않을 데이터"로 읽힙니다.**
- 위치: `P1-req:50, 291, 293-294` / `P1-des:268, 274`
- 문제: Glossary는 Delimiter_Tag를 "검토 대상 데이터 영역" 표시로 정의하고, 14.4는 그 영역의 지시문을 따르지 말고 `security`로 보고하라고 합니다. 설계의 태그 목록에는 `<prlens:team_context>`가 들어 있어, 문자 그대로면 팀 규칙이 "따르지 않을 데이터"가 됩니다. 14.5의 이스케이프 대상에도 컨텍스트 파일 내용과 head 스펙 내용이 없습니다.
- 수정안: "리뷰 기준 영역"과 "검토 대상 데이터 영역"을 용어로 나누고, 14.5에 컨텍스트 내용·head 스펙을 추가합니다.

**9. [오류] Property 18이 설계의 구현과 맞지 않습니다.**
- 위치: `P1-des:632-634` vs `214` / `P1-tasks:173`
- 문제: Property 18은 "임의 추가 순서열"에서 가장 높은 우선순위 출처가 남는다고 합니다. 설계와 작업 8.11의 구현은 "이미 있는 경로는 기존 출처 유지"(먼저 온 것 우선)입니다. spec→claude_md 순서 입력이면 속성이 실패합니다.
- 수정안: 누적기를 우선순위 비교로 바꾸거나, 속성을 실제 수집 순서로 한정합니다.

**10. [누락] 제외 사유가 출력에 나오지 않습니다.**
- 위치: `P1-req:101-102, 105` / `P1-des:209, 413, 855`
- 문제: 제외 사유를 기록하라고 하지만 `ReviewResult.excludedFiles`는 경로 목록뿐입니다. patch가 없는 대형 파일이나 해석 실패 파일은 줄 수 계산에서도 빠지고 결과는 `complete`·종료 코드 0입니다.
- 수정안: `excludedFiles`를 `{path, reason}`으로 넓히거나 확장 필드를 추가하고, Markdown "제외 파일" 구역에 사유를 표시합니다.

**11. [모호] 요약 전용 모드는 CI에서 항상 통과합니다.**
- 위치: `P1-req:277, 314` / `P1-des:366`
- 문제: 요약 전용 모드는 `findings`가 항상 비어 있고 `complete`라서 종료 코드가 0입니다. 상한의 3배를 넘는 PR은 CI에서 항상 통과합니다.
- 수정안: D-4에 포함해 결정합니다(예: 요약 전용은 종료 코드 3 또는 `incomplete` 사유 추가).

**12. [모순] 월요일 선머지 분량이 ROADMAP의 원칙보다 큽니다.**
- 위치: `P1-tasks:5, 14-69` / `ROADMAP.md:18, 56`
- 문제: ROADMAP은 월요일에 인터페이스 타입만 먼저 머지한다고 하는데, tasks는 "각 트랙은 1~4번 작업이 머지된 뒤 시작"이고 여기에 재시도·마스킹 구현과 속성 테스트 4개까지 들어 있습니다(wave 0~4, B 혼자). A와 C가 그동안 대기합니다.
- 수정안: 선머지를 1, 2.1~2.3으로 줄이고, 작업 3은 인터페이스만 먼저 두고 병렬로 진행합니다.

### 경미

**13. [모순] 대상 파일 0개일 때 절단 판정을 건너뜁니다.**
- 위치: `P1-req:74` vs `279` / `P1-des:229, 240`
- 문제: 1.14는 파일 수가 부족하면 `incomplete`, 13.11은 대상 0개면 `complete`입니다. 설계 흐름은 대상 0개에서 먼저 반환해 절단 판정을 건너뜁니다. 같은 분기에서 `modeDecided` 호출(13.12)도 빠집니다.
- 수정안: 대상 0개 분기에서도 절단 판정과 listener 호출을 하도록 순서를 고칩니다.

**14. [참조 오류] Property 2의 검증 위치가 틀렸습니다.**

- 문제: Property 2는 `files_truncated` 기록을 검증한다고 하지만, 그 판정은 `ReviewEngine`(T1, 12.1)이 합니다. T2의 `PrFetcher` 테스트(7.5)로는 확인할 수 없습니다.
- 수정안: 7.5는 순서·중복·개수만 보고, 절단 판정은 12.2로 옮깁니다.

**15. [참조 오류] Property 3으로는 요구사항 2.2를 검증할 수 없습니다.**
