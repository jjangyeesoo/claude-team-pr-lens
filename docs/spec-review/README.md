# PR Lens 스펙 검토 결과 (P1·P2·P3)

- 검토일: 2026-10-04
- 대상: PR Lens 스펙 세 건 `pr-lens-p1-cli`, `pr-lens-p2-automation`, `pr-lens-p3-web` (검토 당시 위치는 `.kiro/specs/`)
  - P1, P2는 요구사항·설계·작업 목록을 모두 검토했습니다.
  - P3는 `requirements.md`만 있어서 요구사항만 검토했습니다.
- 방법: 서브에이전트 8개(P1·P2에 5개, P3에 3개)가 범위를 나눠 문서를 읽고 판정했습니다. 컴파일이나 테스트 실행으로 확인한 것은 없고, 개별 지적을 사람이 다시 검증하지 않았습니다.

## 결론

**세 스펙 모두 그대로는 다음 단계로 갈 수 없고, 수정하면 가능합니다.**

- **P1, P2**: 그대로는 구현에 들어갈 수 없습니다. 문서 사이의 번호 참조는 정확하지만, 두 설계가 "스타터가 없다"는 가정으로 쓰여서 실제 저장소(`claude-team-prlen`)와 여러 곳에서 충돌합니다.
- **P3**: 작은 수정 후 설계에 들어갈 수 있습니다. PRD의 FR-12~14는 모두 덮여 있지만, 화면과 API가 만나는 지점에 모순이 있고 Next.js 16의 동작과 충돌하는 요구가 4군데 있습니다. P1·P2의 에러 형식, API 경로 문제를 그대로 반복합니다.

## 여러 검토에서 겹친 지적

서로 다른 에이전트가 독립적으로 같은 지적을 한 항목입니다. 신뢰도가 높으니 먼저 처리하세요.

| 지적 | 나온 곳 |
|---|---|
| 에러 형식: 스펙은 `ProblemDetail` 또는 미정, 저장소 ADR 0002는 `ErrorResponse` | 01, 03, 04, 06 |
| API 경로: 스펙은 `/api/repositories`, `/api/stats`, 저장소 규칙은 `/api/v1/<복수형>` | 01, 03, 04, 06 |
| 패키지 구조: 스펙은 평면 패키지, 저장소 ADR 0001은 `<feature>.{domain,api}` | 01, 02, 04 |

## 착수 전에 정해야 할 것

지적의 상당수가 아래 결정에서 나옵니다. 결정하면 여러 지적이 한꺼번에 정리됩니다.

1. **ADR 0001 (패키지 구조)**: 스펙의 평면 패키지를 따를지, 저장소의 `<feature>.{domain,api}`를 따를지.
2. **ADR 0002 (에러 형식)**: `ErrorResponse`를 유지하고 스펙을 고치는 쪽을 권합니다. P2 요구사항도 원래 ADR 0002를 따르라고 적고 있고(`P2-req:51`), web 클라이언트가 이미 이 형식을 파싱합니다. P2와 P3에 함께 적용됩니다.
3. **API 경로**: `/api/v1/`을 넣을지, 규칙 예외를 ADR로 남길지. P2와 P3에 함께 적용되고, OpenAPI 작성 전에 정해야 합니다.
4. **ADR 0003~0006**: 저장소 구조, CLI 라이브러리, 모델·effort·최대 출력 토큰, DB·테스트 전략(Docker 테스트 분리 포함).
5. **결정 대기 항목**
   - P1: D-1~D-7과 G-1~G-7 ([02](02-p1-internal.md#결정-대기-항목))
   - P2: D-1~D-12와 spike 13건 ([03](03-p2-requirements-design.md#결정-대기와-spike-항목))
   - P3: D-1~D-12 ([06](06-p3-requirements.md#결정-대기-항목)). 통계 기준인 D-3, D-4, D-12는 4주차 킥오프 전에 확정해야 합니다.
6. **가장 먼저 할 spike**: jqwik이 JUnit 6에서 도는지([05](05-external-facts.md#구현에-영향이-큰-누락)). 안 돌면 속성 테스트 계획 전체가 막힙니다.
7. **P3가 P2에 요구하는 변경**: 페이지네이션, DTO 필드, `ReviewStore` 시그니처 등 16항목([06](06-p3-requirements.md#p3가-p2에-요구하는-추가변경)). P2 구현 전에 반영하면 재작업이 줄어듭니다.
8. **웹 테스트 도구와 의존성**: P3 요구사항이 전제하는 도구(DOM 테스트, E2E, 속성 테스트, OpenAPI 타입 생성, 차트)가 설치되어 있지 않습니다([06](06-p3-requirements.md#설치된-버전)). 무엇을 추가할지와 각 요구를 자동·수동 중 무엇으로 검증할지 정해야 합니다.

## 검토하지 못한 것

- P3의 설계와 작업 목록(아직 작성되지 않음).
- 실제 컴파일, 테스트 실행, API 호출. 예를 들어 "sealed 예외 계층이 컴파일되지 않는다"는 Java 언어 규칙에 근거한 판단입니다. 예외로 06의 C-5(`KST` 표기)와 C-6(반올림)은 설치된 Node에서 직접 실행해 확인했습니다.
- 05의 외부 사실 검증은 공식 문서의 요약을 보고 판정했습니다. 스펙을 고치기 전에 원문을 확인하세요. 06의 Next.js 관련 판정은 설치된 버전에 번들된 문서를 직접 읽은 것입니다.
- 01번 검토는 `requirements.md`와 `design.md`의 본문 전체를 읽지 않았습니다(개요, Glossary, 아키텍처, 오류 처리, 테스트 전략, 결정 대기, spike 표와 grep 결과만).
- 각 문서 끝의 "확인하지 못한 것" 절에 범위별 한계가 따로 적혀 있습니다.
